# 自动重置损坏的启动 Patch 设计

## 意图
Windows 用户启动时，如果账号目录或当前 Profile 的 `cordis.patch.yml` 已损坏、被截断，或根节点不是插件列表，桌面端应自动清空该 patch 并继续启动，避免用户卡在“启动配置恢复”窗口。

## 范围
- 处理 `settings.yaml` 以外的启动 patch：根级 `cordis.patch.yml` 和当前 Profile 的 `cordis.patch.yml`。
- 仅处理 `yaml-format`：YAML 无法解析，或 `.patch.yml` 根节点不是列表。
- 自动替换为带换行的 `[]\n`，随后重新检查配置并返回重试。
- 保留其他配置问题的现有恢复流程；不自动修改模型地址、旧工作流或环境变量。

## 非目标
- 不尝试从备份、临时文件或用户目录推断原配置。
- 不保留损坏 patch 中的插件、模型或自定义配置。
- 不改变插件包自带 patch 的加载与校验规则。

## 方案
已选择“损坏即重置为空列表”。恢复器在扫描到 `yaml-format` 时停止 Host、将目标文件写成 `[]\n`，再重新扫描；扫描无错误后返回 `retry`，由正常启动流程重新构建默认配置。写入继续使用现有受保护路径和原子替换机制，避免把任意路径当成恢复目标。

## 验证
增加回归测试覆盖：根级损坏 patch、Profile 损坏 patch、非列表根结构、自动重置后的重试结果，以及正常列表 patch 不被修改。运行桌面端相关 Vitest 测试和 TypeScript 检查。
